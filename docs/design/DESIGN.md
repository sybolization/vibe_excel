# book 设计规范

> 一句话：这是一本活账本的图纸。内容层是纸和块，控制层是玻璃，两者之间没有第三种东西。
>
> 状态：样张已定（`out/sep/lg.html`，未入库）。`packages/book/app` 仍用旧 token，**尚未迁移**。

## 0. 来源

| 规矩 | 出处 |
| --- | --- |
| 色彩角色、玻璃的使用边界、无障碍三态 | Apple HIG，经 [dickwu/apple-design-skill](https://github.com/dickwu/apple-design-skill) 的镜像摘录：`references/hig/color.md`、`liquid-glass.md`、`materials.md` |
| 中性色阶、字号、圆角、深度、动效刻度 | unslop `references/tokens.md` 的 dark/light 中性列（CC BY 4.0，Damir Sokolovsky） |
| 玻璃的网页实现（共享面、卷边、回退） | [dabit3/liquid-glass-web-skill](https://github.com/dabit3/liquid-glass-web-skill) |

两条最关键的原文：

- HIG 给的是**角色**，不是色板。`color.md` 明确写 documented values are for your reference。所以照角色实现，色值自己定。
- Liquid Glass **本身没有颜色**，只反射背后的内容；品牌色应当放进内容层让玻璃去取样，一条强调色只给主操作和状态。

Apple 的语义灰偏冷（`#f2f2f7`、`rgba(60,60,67,…)`）。本版把中性面收成**不带色相**的 graphite：底色不表态，温度只由强调色承担。角色划分一点不改。

## 1. 方向

- **产品**：一个 Excel 管线的活账本。给写管线的人看：哪几个原始文件、怎么变成十几张表、这次运行碰了哪些。
- **性格**：精确、安静、有一点温度。
- **世界**：点阵本 + 工具箱。纸是点阵纸，块是卡片，连线只有正交。
- **时刻**：画布上那条蓝线（全屏唯一的饱和）；表卡片里的真实数字（数字本身就是质感）。
- **签名**：数据是网格，计算是竖条。

## 2. 三层

| 层 | 是什么 | 铺什么 |
| --- | --- | --- |
| 内容层 | 画布、节点、连边、表、正文 | 纸与块。**不铺玻璃。** |
| 控制层 | 顶栏、底栏、缩放条 | 玻璃。唯一允许玻璃的地方。 |
| 标准材质层 | 左侧「来源」托盘 | 近不透明近白面 + 同一套圆角/描边/内高光/投影。 |

三条判据：

1. 玻璃只给**浮在内容之上、并真的有东西可透**的面。托盘左边是空白方格纸，硬做玻璃就是一块灰板——那是缺陷，不是风格。
2. 装数据的面要更**厚**（越厚越能承载小字）。底栏放真实取样，所以 0.90 不透明；顶栏只有标签，0.72。
3. 一组控件只铺**一块**玻璃，内部按钮透明。缩放条是三个按钮共享一个胶囊。

| `--accent-fill` 强调（面积） | `#2563eb` | `#3b82f6` | 柔面、状态点 |

色温试过的三档（都留着，别再从头试）：

| 底色 | R−B | 反馈 |
| --- | --- | --- |
| `#f2f2f7` | −5 | 冷，像系统灰 |
| `#f7f4ee` | 9 | 暖，像纸 |
| `#f3f3f1` | 2 | **当前**：不带色相，温度交给强调色 |

规矩：底色 |R−B| ≤ 3，不表态。**温度由强调色独家承担**——蓝在带色相的暖底上永远违和，把底色退到中性，问题从根上没了。

色温一次挪四样：**纸**（`--bg` / `--card` / `--raise` / `--sunken`）、**线**、**点阵**、阴影的色。**不动**的是文字三级和强调色。

画布上有四级亮度，都从纸往上抬，方向单一：

```
纸 #f3f3f1  →  sheet #f9f9f7  →  表 / 文件 #ffffff     计算块：不抬，就是纸本身
```

深色同一个方向（离纸越远越亮）：`#16161a → #1e1e24 → #23232a`。**计算块在深色里也是纸**（`#16161a`）。这条定死，否则两组登记的对比会随主题翻向。

规矩：

- **一条强调色**，蓝 `#1d4ed8`（中性底上 6:1）。
- 为什么最后是蓝，而不是更暖的赭石红：红在语义上像报错，run 路径是"发生了什么"而不是"出错了"，读错一次就白画。宁可让颜色偏冷，也不能让主路径被读成失败。
- 蓝只做强调，不铺面积。想压一档冷就把 `--accent` 降到墨蓝 `#3a5a94`（饱和度低一半，代价是线没那么跳），别换色相。
- 强调色只出现在三处：本次运行的连边、选中态、数据已更新。控制层其余部分一律单色。
- **面积不用强调色**：托盘选中行用凹面 `--sunken` + 3px 蓝竖条，不铺色底。
- 只有一种色相。"数据已更新"不再单独用琥珀，直接取强调色——省一个颜色，顶栏只留一处彩。
- `faint` 是"勿用级"：不给任何需要读的字。HIG 明说 thin 材质上禁止 tertiary/quaternary。
- 深色不是反相：面走 `#16161a/#1c1c20/#26262a`，强调色换亮一档 `#7aa2ff`。

## 4. 字体

两个栈，各管一段：

- 正文：`"HarmonyOS Sans SC", -apple-system, "Segoe UI Variable Text", "PingFang SC", …`。文件名、sheet 名、说明、标题，中英混排都在这里。
- 等宽：`"SF Mono", "Cascadia Mono", …`。**只给标识符和数字**：表名、函数名、行×列、耗时、sha、百分比。

为什么：中英混排塞进等宽栈，中文会落到系统 fallback，字宽与基线和数字对不齐，同一行看着一半实一半虚。等宽只留给纯标识符（`raw_available`）就永远对齐。

### 4.1 鸿蒙字体：不能子集化

用的是华为原版 `HarmonyOS_Sans_SC_Regular/Medium.ttf`，**未做任何修改**。

原本打算子集化到页面用到的字，压到 100 KB 级。**不行**——`HarmonyOS Sans Fonts License Agreement` 第 2 条：

> (2) YOU may not make any modifications to HarmonyOS Sans Fonts or any of their individual components.

子集化就是对字体程序的修改。同一节还要求：保留版权声明与本协议（第 4 条）、在软件里显著注明使用了 HarmonyOS Sans（第 1 条）、不得单独分发字体（第 3 条）。

所以只剩三条路：

| 做法 | 体积 | 别人打开是否一致 |
| --- | --- | --- |
| 原样打包 1–2 个字重 + 许可 + 界面注明 | 8.3–16.5 MB | 一致 |
| 只写字体名、不打包，靠本机安装 | 0 | 没装就回退 |
| 脚本本地取字体，二进制不入库 | 0（仓库） | 本机一致 |

样张走的是第三条：字体放在 `out/sep/fonts/`（`out/` 被 gitignore），由本地服务器随页面发出。

验证方式不是"看着像"：`document.fonts.check('12px "HarmonyOS Sans SC"')` 为真，且同一串文字在鸿蒙下量得 160.9px、在 Consolas 下 172.5px——宽度变了，说明真在用，不是回退。

**等宽没有换。** 标识符和数字继续走 `Cascadia Mono/Consolas`：等宽 vs 正文是「机器 / 产物」四个区分通道里的一条，全换成鸿蒙这条就没了。

| 用途 | 字号/行高 | 字重 |
| --- | --- | --- |
| 下限（任何可读的字） | 11 / 14 | 400 |
| 元数据、计数 | 11 / 14 | 400 |
| 次文字、说明 | 12 / 19 | 400 |
| 列表主行、正文 | 12.5–13 / 16–18 | 500 |
| 面板标题 | 14 / 18 | 600 |
| 画布节点名 | 12–12.5 / 16 | 500 |

- 字重只有 400 / 500 / 600。层级靠字号和颜色，不靠字重堆。
- 16px 以下字距为 0，不加负字距。
- 数字一律 `tabular-nums`。
- 不加 `-webkit-font-smoothing: antialiased`，它让字更细。

## 5. 尺寸与圆角

- 4px 网格。行高 32 / 36 / 40 / 48。
- 半径：小控件 8，按钮与输入 8–10，画布数据块 10（sheet 8、计算块 7），卡片 12–16，面板与托盘外壳 14–18，胶囊取高度一半。
- 嵌套半径 = 外半径 − 内边距，不小于 4。
- 可点区域不小于 24×24（桌面），间距不小于 2。

## 6. 深度

- 浅色：贴纸感 `0 1px 2px rgba(30,30,34,.07)`；浮起 `0 12px 32px -14px rgba(30,30,34,.22)` 加 `inset 0 1px 0` 顶高光。
- 深色：只靠面台阶和 1px 内高光，不用彩色投影，不用发光。
- 阴影色跟着纸走（中性 `rgba(30,30,34,…)`），不用纯黑，也不用偏棕——纸退成中性以后，棕色的影子会变成全页唯一的暖调，比底色本身更露。
- **投影只属于对象**。计算块没有投影，取消投影这件事本身就是"它不是一个东西"的信号。

## 7. 玻璃规格

```
backdrop-filter: blur(24px) saturate(150%)
填充：顶栏 .72 / 底栏 .90 / 托盘 .96    （面积越大、字越密，越不透明）
描边：1px 中性 12%，外加 inset 0 1px 0 内高光
投影：0 12px 32px -14px 中性 22%
```

- **卷边**：内容滑到控制层下面之前先虚掉（6px 模糊 + 遮罩渐变），不用实底遮。
- **无障碍**：`prefers-reduced-transparency` → 全部退回不透明面并关掉卷边；`prefers-contrast: more` → 文字加浓、描边加深；`prefers-reduced-motion` → 去掉过渡。

## 8. 画布（内容层）

- 底板是**点阵**，不是横竖线：`radial-gradient` 一格 24，点 1px，13%。只在 24 这一级，不叠 120 的大点——大点会读成"脏斑"，不是节奏。

### 8.1 两组登记：数据是东西，计算是动作

> **这一节是暂定的。** 编码方向（实心 vs 透空）已定成立，但「用哪种编码实现」还没定案：透空只靠 3% 亮度差，离开屏幕尺寸就失效。候选与待决三问见 [`PENDING.md` P0](PENDING.md)，`encodings.png` 是对照图。定案后整节改写。

画布上只有两类，靠**有没有实体**分开，不靠颜色：

| | 数据（文件 / sheet / 表） | 计算（`file:func`） |
| --- | --- | --- |
| 填充 | 实心，亮于纸 | **没有**，点阵纸从它中间穿过去 |
| 投影 | 有（sheet 除外） | 无 |
| 描边 | 1px 14% | 1px 7.5%，更细 |
| 圆角 | 10（sheet 8） | 7 |
| 字体 | 正文字体 | 全篇等宽 |
| 两行 | 名字 / 量（行×列、尺寸） | 函数名 / 耗时 |

- 抄不了就退：缩到 30% 看不清字的时候，一边是实心块，一边是空框，还分得开。这是选"实体 vs 透空"而不是"两种淡色"的原因。
- 透空只有两种含义，不扩用：**这一格是动作**，或**这张表没进这条线**（`meta`、`quarantine` 这类追不到来路的，实心去掉、改虚线）。除了这两处，任何数据块都必须实心。
- **透空不等于失效**。计算块的函数名用正文墨色 `--ink`，只有耗时退到 `--ink2`。第一版把两者都压到次级灰，结果读成"这些步骤被禁用了"。
- 计算的耗时不压在右边——它和函数名各占一行。一行长条右边吊个数字，就是"长条形"的第一来源。
- `--obj` 是纯白而不是 `--card`：`#fcfcfb` 和纸 `#f3f3f1` 只差 3% 亮度，撑不起"实心"这件事，实心一虚，透空那边也就白做了。

### 8.2 尺寸

| 节点 | 尺寸 | 比例 | 形态 | 内容 |
| --- | --- | --- | --- | --- |
| 文件 | 176×68 | 2.59 | 两行（名字可折两行），左侧 2.5px 竖条 | 文件名 / 尺寸 |
| sheet | 122×47 | 2.60 | 两行，左侧 3px 夹签 | sheet 名 / 行数 |
| 表 | 156×60 | 2.60 | 两行白卡，名字 12.5 / 数字 14 | 表名 / 行×列 |
| 计算 | 128×54 | — | 18px 墨点骑在线上 + 两行旁注 | 函数名 / 耗时 |

- 列间距 46；行间距 = 卡片高度 + 14。
- **长宽比 2.5–2.7，由内容反推，不硬套数字。**算法：内边距 20 + 名字行 17 + 数字行 18 = 55，宽度取到刚好放下最长的表名（`available_positions` 19 字 ≈ 124），156/60 = 2.6。文件因为名字折两行而高一些（68），sheet 因为内容少而窄一些（122），三者都落在带内。
- 试过的账：196×28（7:1，读成下划线）→ 172×44（3.9:1，还是条）→ 150×52 → **154×95（黄金分割 1.618，卡片空掉 38%）** → 现在。黄金分割之所以失败：φ 比内容大了一倍，边框里空出的 36px 读成"少了一块内容"，不是"比例"。**比例要由内容反推，不是由数字套上去。**
- 数字升成第二层（14px、`--ink2`、等宽），名字 12.5px `--ink`。两级阶差把卡片下半填满，空出来的只有 5px。
- 卡片里字最少 11，两行的用 12.5 + 11，靠字号分主次，不靠颜色。

- 连边只有正交一种，1.2px；本次运行 1.8px 深蓝；追不到来路的虚线。
- 本次运行：表的描边换蓝；文件只换左侧竖条，不要再套一圈同色边框。
- 位置全部算出来，不手摆。画布可拖可缩放，`适应` 回到全览。

## 9. 动效

一条缓动 `cubic-bezier(.22,1,.36,1)`。hover 与按压 120–180ms，出入 300–500ms。只过渡 color / background / border / opacity / transform，不碰宽高与位置。

## 10. 评审清单

- [ ] 玻璃只在控制层，且下面真的能透出内容
- [ ] 铺了数据的面上没有低于 11 的字
- [ ] 中英混排没有落进等宽栈
- [ ] 一个界面只有一条强调色，蓝只出现在运行、选中与更新提示
- [ ] 强调色不铺面积（选中用凹面 + 竖条，不用色底）
- [ ] 强调色不带错误含义（红、橙不做主色）
- [ ] 节点长宽比 2.5–2.7 且由内容反推，不是硬套一个数字
- [ ] 数据和计算是两套登记：计算块里能看见点阵，且看起来不欠费
- [ ] 只有三级可读文字，`faint` 上没有要读的内容
- [ ] 所有间距是 4 的倍数
- [ ] 嵌套半径自洽（外 − 内边距 ≥ 4）
- [ ] 可点区域 ≥ 24×24
- [ ] reduce-transparency / contrast / motion 三态都有回退
- [ ] 画面里没有第二处高饱和

## 11. 试过的账与待定

> 还没定的不写在这，写 [`PENDING.md`](PENDING.md)。这一节只留「试过并排除」的账。

- **底色已收到中性**：冷灰（`#f2f2f7`）、暖纸（`#f7f4ee`、`#f6f1e7`）都试过，反馈都是"偏了"。现在底色不带色相，蓝只做强调，两边不再互相拽。
- **强调色暂定蓝**：绿（Excel）在带色相的底上是两套系统，赭石红像报错，蓝偏冷但语义最安全。要试更淡的感觉，就把 `--accent` 降到墨蓝 `#3a5a94`，只在色相内调，别换语义。
- **托盘与画布的文件列重复**：五个文件在两处各出现一次。倾向让托盘取代画布的文件列，画布从 sheet 开始——那正好是"数据来源 / 计算流程"的切分。**注意**：这一件事和 §8.1 的两组登记不冲突，也不互相替代——8.1 解决"一眼分得开"，去文件列解决"同一个东西画两遍"。已并入 [`PENDING.md` P0](PENDING.md) 的 Q2。
- **节点做瘦的三次账**：196×28（7:1）读成下划线；172×44（3.9:1）还是条；150×52（2.88）才站住。教训写进 8.2 了：**加高有用，但根因是"名 + 数一行塞"**。
- **「透空 = 计算」被降级**：这一版用 3% 亮度差区分产物与机器，像素上成立、感知上不成立，已退回 `PENDING.md` P0 重选编码。

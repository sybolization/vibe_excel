# 写 pipeline 代码的约定：步骤注释

页面上的「计算过程」和 `vibectl` 的摘要，都从**代码里的一行行说明**读出来。
不写这些说明，节点在页面上就只剩「读什么、写什么」，看不出它到底做了什么。

这套约定由 `vibe_excel/engines/flow_parse._collect_steps` 解析，落进 `run.json`
的 `graph.nodes[].steps`，再由 `book/graph._steps` 变成页面用的步骤视图。

## 三条规则

1. **函数 docstring = 这一步的一句话总结**。它会显示在节点详情最上面那行，
   也是终端摘要里 `节点 (call) | 总结` 的那半句。
2. **块的第一条语句写成字符串 = 这个分支/循环在做什么**。`if` / `for` / `while` /
   `try` 都算；行号取的是这个块的开头那一行。
3. **普通语句前面紧挨着一条字符串 = 那条语句在做什么**。

只有同时具备**行号**和**文本**的条目才会保留，空字符串会被丢掉。
`kind` 取 `block` 或 `statement`，`of` 取 AST 的节点类型名（`Assign` / `For` / `If`）。

## 例子

```python
def clean_positions(raw) -> list[dict[str, object]]:
    """清洗可用岗位表：只留四列，岗位号统一大写去空格，其余三列空值补空字符串。"""
    keep = ["岗位号", "归属主管", "成本中心", "地点"]
    "只保留任务要求的四列，其余列（DL/IDL、岗位描述）不参与汇总"

    rows = [pick(row, keep) for row in raw]
    "岗位号统一成不带空格的字符串（数字型岗位号按整数还原，避免 595617.0）"

    for row in rows:
        "文本列空单元格统一成空字符串，不留 nan / None 这类字面值"
        for key in ("归属主管", "成本中心", "地点"):
            row[key] = "" if row[key] is None else str(row[key]).strip()
    return rows
```

这段代码会在页面上显示成：

```
清洗可用岗位表：只留四列，岗位号统一大写去空格，其余三列空值补空字符串。

计算过程                                        3 步
L12  只保留任务要求的四列，其余列（DL/IDL、岗位描述）不参与汇总
L15  岗位号统一成不带空格的字符串（数字型岗位号按整数还原，避免 595617.0）
L17  for    文本列空单元格统一成空字符串，不留 nan / None 这类字面值

读 raw_available · 写 site_positions
```

终端里是同一份数据：

```
  clean_positions    raw_available -> site_positions (site_board.py:clean_positions) | 清洗可用岗位表…
      [statement] 只保留任务要求的四列，其余列（DL/IDL、岗位描述）不参与汇总 (L12)
      [statement] 岗位号统一成不带空格的字符串（数字型岗位号按整数还原，避免 595617.0） (L15)
      [for] 文本列空单元格统一成空字符串，不留 nan / None 这类字面值 (L17)
```

## 写不好会怎样

- **不写**：页面上这个节点显示「这个节点没有标注步骤」，读写成一行照旧可见
- **写成行尾 `#` 注释**：不会出现在步骤里。解析的是**字符串语句**，不是 `#` 注释
- **写了但代码改了没重跑**：页面显示的是那次运行时的代码快照，不会回填新注释

## 为什么要这么麻烦

`run.json` 是一次的运行轨迹，页面和终端都只读它。步骤说明放在代码里，一次写、
两处显示，不需要额外维护一份文档，也不会和实际代码走散。

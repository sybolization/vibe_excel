# ADR-0004：Git 草稿、发布与授权边界

- 状态：已接受
- 日期：2026-10-30
- 相关：指南 §6.1、§6.2、§6.4、§6.5、§12 S1；ADR-0002（版本模型）、ADR-0003（干净重跑）

## 1. 问题

指南 §6.2 要求「用户开始修改时从 main 创建 draft 分支；发布由用户授权，应用完成校验后合并到本地 main」；§6.5 要求「main 发生非授权变化时，停止发布并报告，不能静默认可」。同时 §6.5 自己承认：本地模拟环境**不能**保证 agent 无法用 bash 改 Git 元数据，首版只能靠流程与日志降低风险。

## 2. 决策

### 决策 1：一个会话一个草稿分支 + 一个独立 worktree

`draft/<sessionId 前 8 位>`，从 main 切出，并用 `git worktree` 挂到 `<store>/sessions/<id>/code`。

原因：一个 Git 仓库只有一个工作区，多个草稿分支无法同时 checkout。用 worktree 之后每个会话有自己的一份文件树，互不干扰，提交也发生在各自的 worktree 里。

（这一点在 M0 阶段没有暴露，因为当时只有一个会话；S1 实现时才发现。）

### 决策 2：提交时机由 Harness 决定，不由模型决定

`commitDraft(sessionId, message)` 是同步 API，没有「自动提交」。指南 §6.2 说「每个稳定交互节点可保存代码 commit」——**什么是稳定节点属于产品判断**，放在 Harness 里，而不是让模型自己决定何时提交。

`commitAll` 在无改动时返回 `null`，这是事实而不是错误；上层据此决定要不要提示。

### 决策 3：发布是三重校验 + 一次非快进合并

`publish()` 依次校验，任一失败即拒绝：

1. **干净重跑已通过**——由调用方传入 `cleanRunPassed`。session 包不自己去跑重跑（那是 runtime 的职责），但也不接受"没跑就发布"。
2. **草稿领先 main**——`git rev-list --count main..draft` 必须大于 0；为 0 时提示无需发布。
3. **main 未被非授权改写**——建会话时把 main 的提交记为 `sessions.base_commit`；发布前用 `git merge-base --is-ancestor <base> main` 检查。失败即报「main 发生了非授权变化：停止发布，请人工核对」。
4. 主工作区干净（不允许在脏状态下合并）。

通过后 `git merge --no-ff` 合入 main，保留「这次发布来自哪个草稿」的历史，并在 `publishes` 表留下 `commit_sha / at / note(证据)`。

### 决策 4：发布记录是**授权事实**，不是正确性标签

`publishes` 表只回答「谁在什么时候、基于哪次干净重跑、把哪个草稿合进了 main」。它**不**回答「这个程序对不对」。这条与指南 §12 S1 的禁止项一致：「把用户发布当作正确性标签」是被明令禁止的。

### 决策 5：不做远程同步，不宣称能防恶意

- 不 `git push`（§6.2：发布到 main 是产品语义，不要求远程 push）。
- 扩展/agent 仍可用 bash 改 `.git` 元数据。本 ADR 的校验是**流程约束**，不是安全边界；真边界见 ADR-0001 缺口 13（Windows 上没有可用的 OS 级沙箱）。

## 3. 验证

`packages/session/test/session.test.ts` 11 项，其中与发布相关的：

- 干净重跑未通过 → 拒绝发布；
- 通过后合入 main、`git show main:main.py` 能看到发布内容、`publishes` 有记录且 note 为证据串；
- 草稿没有新提交 → 拒绝；
- **main 被硬回退到根提交后 → 报「非授权变化」并拒绝**。

## 4. 已知缺口

1. **没有发布前钩子**：任何调用方都可以传 `cleanRunPassed: true` 而不真的跑重跑。当前只防误用，不防谎报。
2. **发布记录没有签名**：本地单用户原型可接受，但不能作为审计证据。
3. **main 的非授权变化只在发布时检查**，运行期间不监控。

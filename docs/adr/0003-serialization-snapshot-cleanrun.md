# ADR-0003：执行串行化、数据库快照与干净重跑

- 状态：已接受
- 日期：2026-10-30
- 相关：指南 §3.3、§6.3、§6.4、§8、§12 S3；ADR-0002（版本模型）

## 1. 问题

指南 §3.3 要求「同一 session 的数据修改串行执行；多个 session 可以并发，但不能共用同一个可写数据库文件」；§6.3 要求数据库快照「不得在活跃写入时随意复制单个文件并宣称完整快照」；§6.4 要求发布前在**全新工作目录**做干净重跑。三件事都必须在 M1 之前有可运行实现。

## 2. 决策

### 决策 1：串行化的第一层是「目录隔离」，锁只是把约束显式化

每个 session 拥有独立的 `work/` 目录与独立的数据库文件。**跨 session 并发因此天然安全**——它们根本不碰同一个 `.db` 文件。真正的约束只发生在同一 session 内部，用一个会话级排他锁表达：

- 锁文件：`<store>/sessions/<sessionId>/.session.lock`，用 `O_EXCL` 独占创建；
- 陈旧回收：持锁进程已死（`kill(pid,0)` 失败且非 EPERM），或持锁时间超过 `staleMs`（默认 30 分钟）；
- 拿不到锁**抛错**，不静默继续——静默继续等于没有串行化。

为什么不用进程内 mutex：Harness 重启后 mutex 消失，锁必须活在文件系统上。

明确边界：这是**同机**锁，不跨机器；它也不防止程序自己绕过（Python 脚本仍可以自己开第二个连接写别处）。

### 决策 2：快照用 `VACUUM INTO`，不复制活跃数据库文件

直接 `copyFile` 一个正在写的 `x.db` 只拿到主文件，WAL 里已提交未 checkpoint 的页会丢——那不是快照，是碎片。

`VACUUM INTO` 在一个读事务里输出一份自洽的数据库文件，是 SQLite 提供的一致副本原语。实现要点：

- 输出到临时文件 → 算 sha256 → 内容寻址落到 `<store>/data-revisions/<sha256>.db`；
- 同一内容只存一份（sha 相同即复用）；
- 不等 checkpoint，也不需要停写。

代价：`VACUUM INTO` 期间持有读锁，大库会阻塞写入。当前数据规模可以接受，规模上来后需要换成增量或定期快照策略——这是显式记下的限制，不是"以后再说"。

### 决策 3：恢复必须先校验、再清 WAL、最后原子替换

顺序固定，不能调换：

1. 复制到 `target.restore-<uuid>` 暂存；
2. `PRAGMA quick_check` —— 不通过就抛错，**绝不覆盖现有数据**；
3. 删除目标库的 `-wal` / `-shm` —— 旧 WAL 会把新数据覆盖回去，表现为"恢复了但数据是脏的"；
4. `rename` 原子替换。

调用方必须持有会话锁（保证没有并发写者）。

### 决策 4：干净重跑用 `git worktree --detach`，而不是复制文件树

`git -C <repo> worktree add --detach <dir> <commit>` 得到的目录：

- **天然全新**（不继承主工作区任何未提交改动）；
- **内容确定**（由 commit 唯一决定）；
- 不需要手动 copy，也不会漏掉隐藏文件。

跑完后收集声明的产物、写 `manifest.json`（含全文件内容哈希），再 `worktree remove --force`。保留 manifest 而不是保留工作目录，避免每次重跑在磁盘上堆一份代码。

### 决策 5：输出比较按文件内容哈希，业务等价由调用方判断

指南 §6.4 明说「不要求 xlsx 二进制哈希完全相同，文件元数据变化不一定是业务差异」。因此 runtime 只提供 `diffRunFiles(a, b)` 给出 `onlyInA / onlyInB / changed`，**是否等价不在这里判断**——把业务口径的判断放进调用方（S4 的 verifier），避免 runtime 越权解释业务。

### 决策 6：干净重跑不带模型凭证

`cleanRerun` 用一份最小环境变量白名单（PATH / SystemRoot / TEMP 等操作系统变量），**不传任何 API key**。理由：重跑执行的是程序代码，不该有模型凭证；顺带也让"重跑结果是否依赖凭证"这个变量消失。

可通过 `VIBE_EXCEL_AS_OF` 固定业务日期，对应指南「固定业务日期等影响结果的参数，避免隐含依赖当前时间」。

## 3. 验证

`packages/runtime/test/runtime.test.ts` 12 项，覆盖：

- 连接仍打开、数据可能只在 WAL 里时，快照依然包含已提交数据；
- 内容相同复用同一快照文件；
- 恢复会清掉陈旧 `-wal`，且坏快照被拒绝、不覆盖目标；
- 锁互斥、陈旧锁回收、死进程锁回收、持锁时 `withSessionLock` 拒绝执行；
- 干净重跑在全新目录执行、工作目录随后移除、确定性程序两次重跑内容一致、依赖当前时间的程序被比对抓出、入口失败退出码如实反映。

## 4. 不做什么

- **不承诺**杀掉所有后代进程（指南 §8）。重跑用 `spawnSync` + 超时，超时只保证直接子进程被终止。
- **不承诺**数据库级隔离：程序仍可自己连别的路径。
- **不做**增量快照或备份轮转，当前是「每次显式快照一个完整副本」。
